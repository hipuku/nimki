# Figma sync

How the [nimki Figma file](https://www.figma.com/design/7EoZah6GtSPR9XQlYWbzAO/nimki) and the code stay the same.

## The rule

Code is the source of truth for values. `tokens/source` holds every colour, size, duration, easing and text style; the Figma file shows them as variables and styles. A value changes in code first and reaches Figma through `figma:out` and the plugin's **Sync from code**. A change made in Figma on purpose is exported and brought back into code with `figma:in`, so the token rules (contrast, gamut, motion caps, visible states) check it before it counts.

Anything else in Figma, such as layouts, components and descriptions, can change freely, but every edit is exported and committed, so CI always compares code with the file as it is. Inside a component, every colour, corner, gap, padding, text and effect is bound to a variable or style, so a component in Figma can only show values code has.

## What is in this folder

| Path                  | What it is                                                                                                                                                                   |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `snapshot/nimki.json` | The latest export of the file's variables, effect styles and text styles, with the time it was taken and each variable's id. Written only by `pnpm figma:in` or `figma:save` |
| `plugin/`             | A development plugin for Figma desktop with two buttons, Export and Sync from code. `code.js` is generated by `pnpm figma:plugin`; do not edit it                            |

## Day to day

Two commands and one plugin cover almost everything.

| Command          | What it does                                                                                                                                                                                                                                                        |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm figma:out` | Regenerates the tokens (the rules check them first; a refused value stops here), then copies what the plugin's **Sync from code** needs. `--print` prints it instead                                                                                                |
| `pnpm figma:in`  | Reads the export the plugin copied, checks its checksum, saves it as the snapshot, writes values changed in Figma into `tokens/source`, regenerates and compares. Ends with **In sync**, or lists what needs a decision. Takes a file path instead of the clipboard |

Set up the plugin once: in Figma desktop, Plugins, Development, Import plugin from manifest, and choose `figma/plugin/manifest.json`. Run **nimki export** in the file to open it.

- **Export** copies the file's export for `figma:in`.
- **Sync from code** takes the paste from `figma:out`, makes the file match code (creating, updating and removing variables, modes and collections under `nimki/`, and effect and text styles), then exports, so the next step is `figma:in`.

The export computes a checksum of its own content inside Figma. `figma:in` recomputes it and refuses an export that changed on the way, so a snapshot is never edited by hand.

## Every command

| Command                       | What it does                                                                                                            |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `pnpm figma:out`              | Regenerates the tokens and copies the sync data for the plugin. `--print` prints it                                     |
| `pnpm figma:in [file]`        | Saves an export, pulls Figma's value changes into `tokens/source`, regenerates and compares                             |
| `pnpm figma:check`            | Compares the snapshot with the variables code generates. Lists every difference                                         |
| `pnpm figma:sync`             | Prints a script for the file that lists what differs from code and changes nothing                                      |
| `pnpm figma:sync --apply`     | Prints the script that makes the file match code, the same change as **Sync from code**                                 |
| `pnpm figma:pull`             | Writes values changed in Figma back into `tokens/source`, and lists what it cannot write. `--dry` lists without writing |
| `pnpm figma:script`           | Prints the export script                                                                                                |
| `pnpm figma:save <file>`      | Checks an export's checksum and saves it as the snapshot. A relative path is read from where the command is typed       |
| `pnpm figma:save --clipboard` | The same, reading the clipboard (macOS)                                                                                 |
| `pnpm figma:fresh`            | Asks Figma when the file was last saved and fails if that is later than the export (needs `FIGMA_TOKEN`)                |
| `pnpm figma:plugin`           | Regenerates `plugin/code.js`                                                                                            |
| `pnpm figma:live`             | Reads the Parity page through the REST API and compares every value on it with code (needs `FIGMA_TOKEN`)               |
| `pnpm -s figma:live --script` | Prints the script that builds the Parity page, for `use_figma`                                                          |
| `pnpm figma:audit`            | Reads every page that holds a component and lists each value inside a component that is not bound (needs `FIGMA_TOKEN`) |

`figma:in` runs `figma:save`, `figma:pull` and `tokens:write` in turn; `figma:out` runs `tokens:write`. The scripts `figma:script` and `figma:sync` print run inside the file through the Figma MCP's `use_figma`, for working without the plugin.

## Every situation

### A variable or style is added or removed

Do what "A value changes in code" says, then run the output of `pnpm -s figma:live --script` in the file through `use_figma`. It rebuilds the Parity page for the new set. The live check fails until it is run. Export and `pnpm figma:in` afterwards, since rebuilding the page saves the file.

### A value changes in code

1. Edit `tokens/source`.
2. `pnpm figma:out`. A value that breaks a rule is refused with the reason, and nothing is copied.
3. In Figma, **Sync from code**, paste, run. It exports when done.
4. `pnpm figma:in`. It prints **In sync**.
5. Commit the source, the generated files and the snapshot together.

### A value is changed in Figma on purpose

1. **Export** in the plugin.
2. `pnpm figma:in`. It writes the new value into `tokens/source`, touching only that value's line, and the rules check it. It prints **In sync**.
3. Commit the source, the generated files and the snapshot.

`figma:in` writes what the source sets directly: durations, easings, spring durations and bounce, offsets, scales, density sizes, radius, fonts, the state-layer amounts, colours (converted back to OKLCH) and aliases. It does not write a value code works out, such as a hover or pressed colour, success, warning or a motion role; it lists it under **Needs a decision** with the setting to change instead. It also refuses a colour that was detached from its ramp step in Figma.

### A value is changed in Figma by mistake

1. `pnpm figma:out`, then **Sync from code** in Figma. Figma is back to code's value.
2. `pnpm figma:in`, commit the snapshot.

### Something other than a value changes in Figma

A new component, a moved layer, a description, a page. **Export**, `pnpm figma:in`, commit the snapshot.

### The library is published

Publishing counts as a save, so freshness fails for any export taken before it. Publish first, then **Export**, `pnpm figma:in` and commit the snapshot. The export carries no other change, so `figma:in` prints **In sync**.

### A small code change

Fixes, tests and docs that do not touch `tokens/source` need nothing from Figma.

### A new component, designed in Figma first

1. Design it with existing variables and styles only, and bind every colour, corner, gap, padding, text and effect inside it. Gaps and padding that change with density bind to the density variables; fixed ones bind to `spacing/`, named after Tailwind's step (`spacing/1-5` is `p-1.5`, with a hyphen because Figma refuses a dot in a name). Corners bind to `radius` or its steps (`radius-md` is `rounded-md`). A value it needs that does not exist yet is added in code first.
2. `pnpm figma:audit` lists anything left unbound.
3. **Export**, `pnpm figma:in`, commit.
4. Build it in code, with a story for every state in the design.

### Contributors

Contributors work in code only. Their pull requests come from forks, which GitHub gives no secrets, so the freshness, live and audit checks skip there with a notice; every other check runs. A contributor's change to `tokens/source` shows in `figma:check`, and a maintainer syncs and exports the file.

## Before a commit

The pre-commit hook runs `scripts/check-figma-staged.mjs` when a commit stages `tokens/`, `registry/styles/`, `figma/snapshot/` or the engine's generated tokens. It refuses the commit if the generated files are stale or the snapshot disagrees with code, and says which command fixes it. Other commits skip it.

## What CI checks

The `Figma parity` workflow runs on every push and pull request, and by hand from the Actions tab. It is a required check on `main`. Every check runs even when an earlier one fails, and the run ends with a summary table that shows each one's result; the workflow passes only when all of them pass.

| Check                | Compares                                                                                                                                                                                                                                                                                                |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Generated tokens     | The committed generated files against a fresh run of the generator                                                                                                                                                                                                                                      |
| Variables and styles | The snapshot against the generated variables: each variable's collection, type, code syntax, scopes and value in every mode, each effect style layer by layer, and each text style's font, weight, size, line height and letter spacing. Numbers match within 0.002, because Figma stores 32-bit floats |
| Freshness            | The file's `lastModified`, read through Figma's REST API, against the snapshot's export time                                                                                                                                                                                                            |
| Live values          | Everything on the Parity page, read through the REST API, against code: every variable a node can bind in every mode, every text style, and every effect style in both colour modes                                                                                                                     |
| Component audit      | Every page that holds a component, read through the REST API: inside each component, every colour, corner, gap, padding, text and effect is bound to a variable or style                                                                                                                                |
| Plugin               | The committed `plugin/code.js` against a fresh `figma:plugin`                                                                                                                                                                                                                                           |

Freshness allows 10 minutes between the export and `lastModified`. Figma stamps the file when its server saves, about a minute and a half after an edit, so an export taken straight after an edit would otherwise look older than the file. A save inside those 10 minutes that changes a colour, a number, a font or a style is still caught by the live check, which reads content rather than time.

## The Parity page

A generated page in the Figma file that binds every variable a node can bind, in every mode, and applies every style. Each frame is set to one mode of one collection, such as `nimki/density / Compact`, and holds a cell per variable:

- a colour fills a rectangle;
- a number sets an auto layout frame's gap, which may be zero or a fraction, unlike a size;
- a string is a text layer's content.

The `Text styles` frame holds a text layer per text style, and `Effect styles / Light` and `/ Dark` a rectangle per effect style, so their bound colours resolve in both modes.

The live check reads the page through Figma's REST API, which works on any plan, and compares every value with code. The export is made by a script inside Figma, so a fault in that script would hide a difference from the values check; the live check reads the file another way, so it catches that. Durations and easings cannot be bound to a node, so they are checked through the export and freshness only.

Never edit the page by hand. A cell, frame or style that is missing, extra or shows nothing fails the check with an instruction to rebuild the page.

## The component audit

The audit reads every page that holds a component and walks each component. A visible solid fill or stroke must be bound to a colour variable, and a gradient or image paint fails. A corner above zero, and an auto layout gap or padding above zero, must be bound to a variable; a space-between gap is worked out by Figma and skipped. Text needs a text style and a visible effect an effect style. An instance's own properties are checked, and its insides are checked in its main component. The board around a component set, its panels and previews, are not part of a component and are not checked.

Sizes and stroke widths are not audited. Heights bind to the density variables where a component's brief says so; the rest are Tailwind's fixed sizes, which the binding check compares with the component's code once it exists.

## When a check fails

| Message                                                   | What happened                                                           | Fix                                                                                                                                             |
| --------------------------------------------------------- | ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `The Figma file and tokens/source disagree in N place(s)` | A value differs; the lines name each one, with Figma's value and code's | If code is right: `figma:out`, Sync from code, `figma:in`. If Figma is right: Export, `figma:in`                                                |
| `Figma has changes that are not in the snapshot`          | The file was saved after the last export, or the library was published  | Export and `figma:in`                                                                                                                           |
| `The snapshot has no export time`                         | The snapshot predates timed exports                                     | Export and `figma:in`                                                                                                                           |
| `FIGMA_TOKEN expired or invalid`                          | Figma refused the token                                                 | Make a new token (below) and update the secret                                                                                                  |
| `The Parity page and code disagree`                       | A value on the page differs from code's, or the page is out of date     | If a value differs: Sync from code, or export and `figma:in`. If the page is out of date: run `pnpm -s figma:live --script` through `use_figma` |
| `value(s) in components do not come from a token`         | A component has an unbound colour, corner, gap, padding, text or effect | Bind each named value in Figma, then export and `figma:in`                                                                                      |
| `FIGMA_TOKEN is not set`                                  | The secret is missing on a branch of this repository                    | Add the secret (below)                                                                                                                          |
| `The token rules refused the change`                      | `figma:out` or `figma:in` regenerated and a value broke a rule          | Fix `tokens/source` and run it again                                                                                                            |
| `The export's checksum does not match`                    | The export changed between Figma and the repository                     | Export again; never edit an export                                                                                                              |
| `it is from an older plugin`                              | The export has no text styles                                           | `pnpm figma:plugin`, reload the plugin in Figma, export again                                                                                   |

## Access

Freshness, the live check and the audit read the file through Figma's REST API with a personal access token, stored as the repository secret `FIGMA_TOKEN`. It needs one scope, `file_content:read`, and nothing that writes.

To make or replace it: in Figma, Settings, Security, Personal access tokens, generate a token with only `file_content:read`, then:

```bash
gh secret set FIGMA_TOKEN -R hipuku/nimki
```

and paste the token when asked. Tokens expire; when one does, the check fails with `FIGMA_TOKEN expired or invalid`.

## Limits

- **Variables are read through the export and the Parity page.** Figma's variables API needs an Enterprise plan, so CI cannot list variables directly; the file's `lastModified` and its layers are readable on any plan, which is how freshness, the live check and the audit work. A variable added in Figma alone shows up only in the export, which is why freshness stays strict.
- **Motion is checked as variables only.** Figma cannot run motion or bind a duration or easing to a node; the roles are signed off in code.
- **Publishing the library is manual,** and Figma counts it as a save. After a variable change, publish, then export and `figma:in`.
- **Figma changes made while exploring** belong in a Figma branch or a copy of the file; freshness watches only the main file.
