# Figma sync

How the [nimki Figma file](https://www.figma.com/design/7EoZah6GtSPR9XQlYWbzAO/nimki) and the code stay the same.

## The rule

Code is the source of truth for values. `tokens/source` holds every colour, size, duration and easing; the Figma file shows them as variables. A value changes in code first and reaches Figma through `figma:sync`. A change made in Figma on purpose is brought back into code with `figma:pull`, so the token rules (contrast, gamut, motion caps, visible states) check it before it counts.

Anything else in Figma, such as layouts, components and descriptions, can change freely, but every edit is exported and committed, so CI always compares code with the file as it is.

## What is in this folder

| Path                  | What it is                                                                                                                                        |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `snapshot/nimki.json` | The latest export of the file's variables and effect styles, with the time it was taken and each variable's id. Written only by `pnpm figma:save` |
| `plugin/`             | A development plugin for Figma desktop that runs the export and copies it. `code.js` is generated by `pnpm figma:plugin`; do not edit it          |

## Commands

| Command                       | What it does                                                                                                            |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `pnpm figma:check`            | Compares the snapshot with the variables code generates. Lists every difference                                         |
| `pnpm figma:sync`             | Prints a script for the file that lists what differs from code and changes nothing                                      |
| `pnpm figma:sync --apply`     | Prints the script that makes the file match code: creates, updates and removes variables, modes and effect styles       |
| `pnpm figma:pull`             | Writes values changed in Figma back into `tokens/source`, and lists what it cannot write. `--dry` lists without writing |
| `pnpm figma:script`           | Prints the export script, to run through the Figma MCP's `use_figma`                                                    |
| `pnpm figma:save <file>`      | Checks an export's checksum and saves it as the snapshot. A relative path is read from where the command is typed       |
| `pnpm figma:save --clipboard` | The same, reading the export the plugin copied (macOS)                                                                  |
| `pnpm figma:fresh`            | Asks Figma when the file was last saved and fails if that is later than the export (needs `FIGMA_TOKEN`)                |
| `pnpm figma:plugin`           | Regenerates `plugin/code.js` from the export script                                                                     |

The scripts `figma:sync` prints run inside the file through the Figma MCP's `use_figma`.

## Exporting

1. Run the export:
   - **Plugin:** in Figma desktop, Plugins, Development, Import plugin from manifest, and choose `figma/plugin/manifest.json` (once). Then run **nimki export** in the file. It copies the export.
   - **use_figma:** run the output of `pnpm figma:script` in the file and save what it returns to a file.
2. `pnpm figma:save --clipboard`, or `pnpm figma:save <file>`.
3. Commit `snapshot/nimki.json`.

The export computes a checksum of its own content inside Figma. `figma:save` recomputes it and refuses an export that changed on the way, so a snapshot is never edited by hand.

## Every situation

### A value changes in code

1. Edit `tokens/source`.
2. `pnpm tokens:write`. The rules check the new value; a value that breaks one is refused with the reason.
3. `pnpm figma:sync --apply`, and run the printed script in the file.
4. Export and `pnpm figma:save`.
5. Commit the source, the generated files and the snapshot together.

### A value is changed in Figma on purpose

1. Export and `pnpm figma:save`. `pnpm figma:check` now lists the change.
2. `pnpm figma:pull`. It writes the new value into `tokens/source`, touching only that value's line.
3. `pnpm tokens:write`. The rules check it.
4. `pnpm figma:check` passes. Commit the source, the generated files and the snapshot.

`figma:pull` writes what the source sets directly: durations, easings, spring durations and bounce, offsets, scales, density sizes, radius, fonts, the state-layer amounts, colours (converted back to OKLCH) and aliases. It does not write a value code works out, such as a hover or pressed colour, success, warning or a motion role; it names the setting to change instead. It also refuses a colour that was detached from its ramp step in Figma.

### A value is changed in Figma by mistake

1. `pnpm figma:sync --apply`, and run the script. Figma is back to code's value.
2. Export, `pnpm figma:save`, commit.

### Something other than a value changes in Figma

A new component, a moved layer, a description, a page. Export, `pnpm figma:save`, commit the snapshot.

### A small code change

Fixes, tests and docs that do not touch `tokens/source` need nothing from Figma.

### A new component, designed in Figma first

1. Design it with existing variables only. A value it needs that does not exist yet is added in code first.
2. Export, save and commit.
3. Build it in code, with a story for every state in the design.

### Contributors

Contributors work in code only. Their pull requests come from forks, which GitHub gives no secrets, so the freshness check skips there with a notice; every other check runs. A contributor's change to `tokens/source` shows in `figma:check`, and a maintainer syncs and exports the file.

## What CI checks

The `Figma parity` workflow runs on every push and pull request, and by hand from the Actions tab. It is a required check on `main`.

| Check                | Compares                                                                                                                                                                                                                          |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Variables and styles | The snapshot against the generated variables: each variable's collection, type, code syntax, scopes and value in every mode, and each effect style layer by layer. Numbers match within 0.002, because Figma stores 32-bit floats |
| Freshness            | The file's `lastModified`, read through Figma's REST API, against the snapshot's export time                                                                                                                                      |

Freshness allows 10 minutes between the export and `lastModified`. Figma stamps the file when its server saves, about a minute and a half after an edit, so an export taken straight after an edit would otherwise look older than the file.

## When a check fails

| Message                                                   | What happened                                                           | Fix                                                                                                   |
| --------------------------------------------------------- | ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `The Figma file and tokens/source disagree in N place(s)` | A value differs; the lines name each one, with Figma's value and code's | If code is right: `figma:sync --apply`, export, save. If Figma is right: `figma:pull`, `tokens:write` |
| `Figma has changes that are not in the snapshot`          | The file was saved after the last export                                | Export and `figma:save`                                                                               |
| `The snapshot has no export time`                         | The snapshot predates timed exports                                     | Export and `figma:save`                                                                               |
| `FIGMA_TOKEN expired or invalid`                          | Figma refused the token                                                 | Make a new token (below) and update the secret                                                        |
| `FIGMA_TOKEN is not set`                                  | The secret is missing on a branch of this repository                    | Add the secret (below)                                                                                |
| `The export's checksum does not match`                    | The export changed between Figma and the repository                     | Export again; never edit an export                                                                    |

## Access

Freshness reads the file through Figma's REST API with a personal access token, stored as the repository secret `FIGMA_TOKEN`. It needs one scope, `file_content:read`, and nothing that writes.

To make or replace it: in Figma, Settings, Security, Personal access tokens, generate a token with only `file_content:read`, then:

```bash
gh secret set FIGMA_TOKEN -R hipuku/nimki
```

and paste the token when asked. Tokens expire; when one does, the check fails with `FIGMA_TOKEN expired or invalid`.

## Limits

- **Variable values come through the export.** Figma's variables API needs an Enterprise plan, so CI cannot read them directly; the file's `lastModified` is readable on any plan, which is how freshness works.
- **Motion is checked as variables only.** Figma cannot run motion; the roles are signed off in code.
- **Publishing the library is manual.** After a variable change, the library is republished in Figma so other files see it.
- **Figma changes made while exploring** belong in a Figma branch or a copy of the file; freshness watches only the main file.
